# Self Eval（NOI / OI 比赛预测试）

简体中文 | [English](Self-Evaluation.md) | [Wiki 首页](Home.md)

Self Eval **只用于 NOI / OI 赛制比赛**，由比赛管理员选择开启，默认关闭。IOI、严格 IOI、ICPC / ACM 和普通题库不提供此功能；提交列表及提交详情中不提供 Self Eval 按钮。

选手在比赛题目页点击 **Self Eval**，填写代码、选择比赛允许的语言和编译选项，点击 **运行 Self Eval**。系统在固定、隐藏的预测试集上评测，只显示状态、得分、子任务得分、时间与内存。预测试输入、答案、程序输出、编译诊断、checker 信息不会公开。Self Eval 不创建正式提交，也不改变正式成绩、通过数和排行榜；NOI 的正式提交成绩仍按赛制隐藏。

## 管理员启用与准备

1. 编辑比赛，将赛制设为 **NOI / OI**，勾选 **开启 Self Eval**，设置每位选手全场最大次数并保存。默认 30 次，可设置 1～1000 次，所有比赛题目共用额度。
2. 将传统代码题加入比赛。从比赛题目页点击 **Self Eval**，找到 **配置 Self Eval**。
3. 在两个代码编辑器中填写生成当前正式评测数据的 **make.cpp** 和 **std.cpp**。代码按 C++17 编译，每份源码最多 1 MiB。
4. 确认子任务 ID。若 std.cpp 使用文件输入输出，填写它实际使用的输入和输出文件名。
5. 勾选确认这些程序用于生成当前正式数据，然后点击 **保存 make.cpp / std.cpp**。
6. 点击 **准备预测试数据**，刷新并等待数据状态变为 Ready。保存程序和准备数据必须在比赛开始前完成。

配置 Self Eval 需要比赛管理权限、题目修改权限及编辑测试数据权限。选手运行需要参与比赛、提交题目和运行预测试自评测权限；题目、比赛及团队访问规则仍适用。

系统为源码计算哈希，并保存不可变的版本。预测试使用相同的正式数据生成器和标准程序；**SPJ / checker 直接使用题目当前正式评测配置，无需另外填写 SPJ**。若 AI 正式数据已绑定输入校验器，预测试自动沿用它。手工配置只需要 make.cpp 和 std.cpp，不需要另外提交校验器。

make.cpp 每次接收子任务 ID 和平台生成的案例参数：命令行参数为 `subtaskId seed`，标准输入同样为 `subtaskId seed\n`；输出一份完整输入。std.cpp 读取生成的输入并输出标准答案。平台为每个比赛与题目上下文生成一次固定集合，所有选手使用相同数据。

## 使用 AI

配置区提供 **AI 生成正式数据与 Self Eval 程序** 按钮，需要 AI 使用与生成数据权限，以及可用的 AI API 和评测机。该按钮运行现有正式数据生成流程，**会更新题目的正式评测数据**，并自动绑定同版本的 make.cpp、std.cpp 及输入校验器。

任务完成后，配置区自动读取生成的程序；管理员再点击 **准备预测试数据**。在普通题目编辑页生成正式数据，也会保存同版本程序供之后的 NOI 比赛使用，但不会给普通题库开放 Self Eval。

## 配额和数据限制

- 默认每位选手全场 30 次；管理员可调整，所有题目共享，次数不每日重置。
- 只在比赛开始至结束期间运行。成功创建自测记录时即扣一次，编译错误、错误答案、超时或运行时系统错误不自动返还。
- 数据未就绪、参数不合法、权限不足或准备数据失败不会扣次数。
- 同一账号最多同时有 3 条待评测自测；并发请求按原子额度计数，不能超额。
- 最多 20 个子任务，每个配置的子任务生成 1 组预测试数据。每份输入和答案分别最多 4 MiB，整个 base64 编码后的 JSON 数据集最多 16 MiB。

这些是 LLMOJ 的可配置实现，不代表所有 NOI 赛事都采用同一次数限制。Self Eval 通过不保证正式评测满分。

正式评测配置或程序版本变化会使已准备的数据失效。已使用过的预测试集不能在同一比赛上下文中替换，以避免选手测试不同数据；需要新上下文。比赛进行后不能补配或重新准备预测试数据。

## 提交预览

在 **评测** 和 **我的提交** 列表中，点击提交的状态、分数或语言即可在预览窗口中查看详情；在比赛的提交列表中点击提交编号。列表保持原样，筛选、页码和滚动位置都不变。**Hack** 列表也是如此：点击状态或时间打开 Hack 详情，点击目标提交编号打开那份提交（见 [Hack](Hacks.zh-CN.md)）。

预览窗口显示提交的原页面（1100 × 720 像素，小屏幕上相应缩小），只是隐藏了网站顶部导航，因此代码、测试点、下载、处罚、Hack 和实时更新都照常工作，权限也与原页面相同。比赛规则同样适用，例如 NOI / OI 比赛期间只显示编译结果。

- 点击预览标题中的 **#编号** 打开完整页面；比赛提交会在比赛内打开。Ctrl/Cmd 单击、Shift 单击、中键单击和复制链接与普通链接相同。
- 点击 **×**、按 **Escape** 或点击窗口外部关闭预览。若预览中打开了对话框或菜单，Escape 先关闭它们。较长的页面在预览窗口内滚动。
- 预览中的链接在预览内打开；在预览中打开的列表使用普通链接，不会再嵌套预览。
- 没有访问权限或提交已被删除时，预览显示原页面的错误提示，不会显示代码。预览不会提供超出原页面的权限。

## 实时更新

提交评测期间，它的页面和评测列表会实时更新。连接中断时页面会提示并自动重试，无法重新连接时会提供刷新按钮。评测完成时读屏软件会读出结果。见[键盘与读屏软件](Accessibility.zh-CN.md#实时更新)。

## 答案压缩包

对于 **提交答案** 题，提交的 ZIP 压缩包中包含各个输出文件。评测机只读取题目需要的文件，按压缩包中的文件名匹配：UTF-8 文件名，或来自中文 Windows 的 GB18030 文件名。测试点的结果：

| 结果 | 情形 |
| --- | --- |
| **Output Limit Exceeded** | 文件超过输出限制，或压缩包中排在它前面的文件已占满 4 GiB，它放不下。 |
| **File Error**，“The archive contains this file more than once.” | 同名文件出现两次，包括只在 Unicode 形式上不同的名字（é 写成一个字符或两个字符）。以前会评测其中最后写入的那个。 |
| **File Error**，“This file inflates to more bytes than the archive says it holds.” | 文件数据比压缩包记录的大小更大。一旦超过该大小，解压立即停止。 |
| **File Error**，“This file's data in the archive is damaged …” | 文件数据无法解压，或与记录的大小、校验和不符。 |
| **File Error**，“The archive uses a feature that isn't supported …” | 文件已加密，或使用了 stored 和 deflated 以外的压缩方式。 |
| **File Error**，“The submitted file isn't a ZIP archive that can be read.” | 整个压缩包无法读取：不是 ZIP 文件、文件被截断，或超过 65,536 个条目。所有测试点都得到此结果。以前这会导致 **System Error**。 |
| **File Error**（无消息） | 压缩包中没有该文件，与以前相同。 |

压缩包中的其他文件会被跳过，不会解压。每次评测（包括重测）都解压到自己独立的私有目录，评测机在接下一个任务之前将其删除。如果评测机磁盘的剩余空间不足以容纳压缩包所声明的文件再加 256 MiB，提交以 **System Error** 结束，而不会把磁盘写满。

## 校验器的分数

自定义校验器给每个测试点一个 0 到 100 的分数：

| 校验器 | 分数 |
| --- | --- |
| testlib，`points X`（`quitp`） | X，保留小数部分：`points 37.5` 得 37.5 分。以前会舍去小数部分（37）。 |
| testlib，`partially correct (N)`（`_pc`） | N / 2，保留小数部分：N = 75 得 37.5 分（以前为 37） |
| Lemon、旧版校验器 | 写出的整数 |

分数必须是完整的一个记号，以空格或消息结尾结束。格式错误的分数（`points 37abc`、`1e2`、`-5`、Lemon 写出的小数）或超过 100 的分数（`points 100.9`）视为校验器出错：结果为 **Judgement Failed**，并给出原因。以前这样的分数会被截断（37、100）。与以前一样，报告 `ok` 的 testlib 校验器必须正常退出。已评测的分数在重测之前不会改变。

## 测试数据版本与此前的评测结果

提交按照提交时题目的评测数据进行评测：评测设置、测试数据文件以及要运行的样例构成一个 **数据版本**，每道题目单独编号（#1、#2……）。此后修改题目，不会改变正在等待的提交的评测方式；修改之后的提交使用新版本。**重测** 总是使用题目当前的数据。

- 能够重测该提交的用户可以在结果下方看到它的数据版本，并标明 **当前** 或 **已有变更**。引入数据版本之前的提交不显示版本；重测后会获得版本。
- 被替换或删除的测试数据文件，在仍有需要时会保留（见[已移除的测试数据保留多久](#已移除的测试数据保留多久)）。被删除的附件会立即删除。
- 重测会保留被它替换的结果。能够重测该提交的用户可以在 **此前的评测结果** 中看到最近五次：每次被替换的时间、状态、分数、时间、内存、数据版本和评测环境。删除提交时一并删除。

### 已移除的测试数据保留多久

数据版本记录了它的测试数据文件，但只有这些文件仍然存在时，才能用同样的数据重新评测结果。测试数据被替换或删除后，文件不会立即删除。每十分钟一次的清理会删除不再被需要的文件：

- **总会保留：** 等待中的提交的数据版本所用的文件、等待中的 Hack 或自测所用的文件，以及题目管理者选择保留的数据版本。每个被移除的文件也至少保留 15 分钟。
- **按网站策略保留**（**网站管理** 的 **已移除的测试数据**）：比赛提交所用的文件在比赛进行期间以及结束后 30 天内保留；评测结果所用的文件在移除后 7 天内保留，重测替换这类结果后也再保留 7 天。管理员可以修改这两个天数；设为 0 表示除总会保留的情况外不再额外保留。

能够重测该提交的用户可以在数据版本旁以及 **此前的评测结果** 中看到该版本的测试数据是否仍然齐全：

- 题目仍在使用全部数据时，不额外显示；
- 部分数据已被移除时，显示 **测试数据保留至** 某日，或 **在需要期间保留**。把鼠标移到上面可以看到保留原因；
- 有文件已删除时，显示 **测试数据已删除**：结果保持不变，但无法用同样的数据重新评测。仅有版本号并不代表数据仍然存在。

较早版本旁的 **保留** 会一直保留它的测试数据，直到有人点击 **取消保留**，不受策略影响，例如在申诉期间。这需要编辑该题目的权限；部分数据已删除后会被拒绝。保留和取消保留都会记入审计日志。

**网站管理** 显示仍然存在的已移除测试数据有多少，以及下次清理的预演：每个被移除的文件、它的题目和数据版本、清理会删除还是保留它、保留到何时以及原因。清理做出同样的决定，并在删除前再判断一次，因此期间被保留的版本会保住它的文件。

重测仍然使用题目当前的数据；保留较早版本的测试数据不会改变这一点。

### 内容哈希

每个存储的文件在被接受时都会记录 SHA-256：上传的测试数据、附件和答案文件、导入的压缩包，以及 AI 和自测添加的文件。引入此功能之前存储的文件由后端在后台计算，每分钟最多 1 GiB；`deploy/doctor.sh` 会显示剩余数量。数据版本记录其测试数据文件的哈希；题目管理者在题目的文件页面把鼠标移到文件大小上即可看到它的 SHA-256。

评测前，评测机会用哈希检查每个测试数据文件和每个提交的答案文件，包括它从之前任务中保留的副本。损坏的副本会重新下载。如果某个文件被接受后存储内容发生了变化，该提交会以 **System Error**（“… doesn't match its recorded content”）结束，而不会用与其他评测机不同的数据评测；请重新上传该文件，然后重测。尚无哈希的文件照旧使用。

### 评测环境

能够重测该提交的用户还可以看到评测其结果的环境：评测机、**评测程序**（评测机源文件的摘要）和 **沙箱镜像**（标识其编译器和解释器）。点击可查看 Node.js 版本、系统和 CPU。**此前的评测结果** 对每个被替换的结果显示同样的信息。引入此功能之前的结果，以及协议版本低于 3 的评测机给出的结果，显示 **未记录**。

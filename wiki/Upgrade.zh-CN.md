# 保留配置与数据的一键升级

简体中文 | [English](Upgrade.md) | [Wiki 首页](Home.md)

本工具用于**已完成官方一键安装的 `all` 或 `web` 实例**，更新应用代码和网页资源，同时保留已有账号、题目、提交、对象存储、AI 配置及主密钥、评测槽数、CPU 绑定和原有服务定制。它不会重新运行安装器或初始化管理员。

## 适用范围

本版支持官方 version-3 安装元数据、本机 MariaDB／Redis／MinIO、单实例后端及 Node 24.21.0 / pnpm 11.13.1 的已知布局。运行时、依赖锁文件、共享包、评测程序和 rootfs 配方须与目标版本兼容；本次仅允许已知注册审核表结构变更、将上一版未激活空账户迁为独立注册申请的数据迁移，以及在 `user_privilege.privilegeType` 已知枚举末尾追加 `ManageRegistrationReviews`。追加权限会先核对全部旧枚举值和顺序；删除、重命名、重排或其它未知值均不在自动升级范围。

仓库链接、组件描述及 bootstrap 显示标题的本次品牌修正不会被误判为依赖变化：升级器仅允许指定文件中的已知 LibreOJ → LLMOJ 文案／仓库地址变换，包名、依赖、脚本、API／CDN 地址及其他配置仍须符合原兼容要求。源码完整性检查仍使用原始文件内容。

默认实例服务与 AI／临时文件目录须保持官方布局；后端或评测通过 `EnvironmentFile` 注入环境、将 AI 主密钥或工作目录改到其它位置时，本版会拒绝自动处理。已有 CPU 绑定、评测槽数和内存限制等受支持的服务定制会保留。

它**不承诺从任意历史版本升级**。Git 管理的部署、未知安装布局、自定义数据库连接、未知数据库结构改动或依赖／原生模块变化会被拒绝，应先设计相应迁移。拒绝预检不会覆盖配置，也不应通过删除旧数据或重新安装来绕过。

## 一键运行

先确认目标文件已上传到 GitHub。中文入口：

```bash
curl -fsSL https://raw.githubusercontent.com/houyhlouis/LLMOJ/main/upgrade.zh-CN.sh -o /tmp/llmoj-upgrade.zh-CN.sh && \
  sudo bash /tmp/llmoj-upgrade.zh-CN.sh --prefix /opt/LibreOJ
```

自定义安装目录请替换 `--prefix`。脚本将 `main` 解析为固定的完整提交，再下载该提交的完整源码，避免下载期间分支变化混用版本。可通过 `--ref 完整提交SHA` 选择已审阅的提交；这不能绕过兼容性检查。

只读预检：

```bash
sudo bash /tmp/llmoj-upgrade.zh-CN.sh --prefix /opt/LibreOJ --plan
```

`--plan` 检查部署与运行时，并列出尚未完成的检查；它不会构建、创建数据库副本或停服务，因此**预检通过不等于升级已完成**。完整源码的构建和数据库副本迁移验证在实际升级的暂存阶段进行。

## 维护窗口与执行过程

开始前暂停新提交、出题导入和 AI 任务，等待正在运行及排队的任务结束；远程评测节点也必须排空。脚本会要求在终端输入 `UPGRADE` 确认。它会再次检查数据库中的活动任务，但不能自动替你协调所有远程节点。

1. 获取实例维护锁，核对服务实际使用的目录、配置、来源、磁盘空间和运行时。
2. 在实例的私有备份目录内复制独立的构建环境，构建后端、前端并验证网页资源清单，不写入正在运行的依赖目录。
3. 备份配置、AI 主密钥和数据库；将数据库备份恢复到临时库，审查并试运行已知的表结构变更和注册申请迁移。不兼容则在切换前停止。
4. 在维护窗口停止 Nginx、评测及后端，重新备份数据库并复查迁移，再切换代码和网页资源。
5. 检查新后端及原先启用的本机评测，最后恢复网页入口。服务恢复到升级前的启停状态；原本未运行的服务不会被永久开启。

备份在 `<安装目录>/backups/upgrade/<时间-随机后缀>/`，路径会显示在终端。SQL、配置、构建日志等备份是 root 私有文件，可能包含敏感信息，**不要上传 GitHub**。脚本保留备份，升级成功后请按自己的保留策略管理；本工具不会删除已有题库、评测数据或旧备份。注册审核旧版产生的未激活空账户会按下方严格规则迁为独立申请。

升级器新增独立服务配置：

```text
/etc/systemd/system/libreoj-backend.service.d/90-libreoj-schema-sync.conf
```

它将 `LIBREOJ_SCHEMA_SYNC=0` 固定到后端服务，禁止启动时自动改表；迁移由升级器在备份及检查后执行。已有同名自定义文件会被拒绝覆盖。其它 systemd 配置、Nginx、数据库密码、API Key 和评测配置保留。

## 从上一版注册审核迁移

新版待审核／已拒绝申请不创建主站账户，通过时才分配用户 ID。升级器在数据库副本中先验证旧申请迁移，并在正式停服务后重新检查、事务执行：

- 保留已有正式账户及已通过审核账户的 ID、密码与业务数据。
- 将符合旧版默认值的未激活空账户转为独立申请，保存密码哈希、申请时间及审核记录；清除对应空账户记录，旧 ID 不回收。
- 旧账户存在内容、权限、定制资料、未知关联、跨库外键或身份冲突时，拒绝迁移，保留原数据，等待人工审查。正常拒绝操作产生的审核日志保留用于追溯。
- 不把旧备份直接导回覆盖当前数据。数据迁移成功后若部署切换失败，旧代码可能不识别新申请，自动回滚会保守拒绝并保持应用停止，应修复新版部署后开放。

不能只覆盖前端文件或删除旧审核表来完成升级。完整状态规则见 [注册审核](Registration-Approval.zh-CN.md)。

## 无人值守与本地完整源码

确认维护窗口已排空后，无交互运行可用：

```bash
sudo bash /tmp/llmoj-upgrade.zh-CN.sh --prefix /opt/LibreOJ --apply --drained
```

`--drained` 是操作者对维护状态的明确声明，不是自动取消任务的指令。不要对仍有用户操作、远程评测或 AI 作业的站点添加这个参数。

已经有经过审核的**完整源码**时，可以使用其中的入口；不能把只含修改文件的 ZIP 当作完整源码：

```bash
sudo bash /path/to/LLMOJ/deploy/upgrade.sh \
  --prefix /opt/LibreOJ --source /path/to/LLMOJ --plan
```

预检显示 `sourceSha256`。核对来源及文件内容后，在实际执行时同时提供 `--source /path/to/LLMOJ --source-sha256 完整64位哈希`。也可用 `python3 /path/to/LLMOJ/deploy/upgrade.py --source /path/to/LLMOJ --source-digest` 只读计算源码树哈希。哈希用于发现内容变化，本身不能证明未经核验的源码可信。

## 失败、重试与回滚

构建或数据库副本校验失败时，原运行实例保持原版本。进入维护切换后失败时，脚本尝试恢复原代码和服务状态；如自动恢复失败，会明确报告并保持应用服务停止，保留恢复记录。不要在看到失败信息后假定已升级或已恢复。

完成故障排查后可用相同参数重试。注册审核的建表及申请迁移可重复执行，已迁移的申请不会重复创建；未知结构变更仍会拒绝。不要删除数据库、私有配置或密钥来重试。

需要手动回滚时，先排空并暂停业务，使用日志中的**本实例备份目录**：

```bash
sudo bash /opt/LibreOJ/deploy/upgrade.sh --prefix /opt/LibreOJ \
  --rollback /opt/LibreOJ/backups/upgrade/实际备份目录 --drained
```

回滚代码和升级器自身的服务配置，保留数据库、对象存储及兼容的新增审核／申请表，**不会把旧 SQL 备份覆盖到现在的数据库**，因此不会主动丢弃升级后的提交。存在待审核或被拒绝的旧账号或新版申请时，本版会保守拒绝代码回滚，防止旧代码绕过审核门槛；应保留支持审核的版本并修复问题。如果在停服务后的复查中发现新产生的未激活账号，服务会保持停止，须恢复支持审核的版本后再开放。SQL 备份用于独立灾难恢复，不是日常降级按钮。

如果这次升级迁移过旧待审核／已拒绝的未激活空账号，即使后来这些申请全部获批，脚本仍拒绝按该备份进行普通代码回滚，避免旧代码无法识别已迁移的申请和审核历史。应修复新版部署；需要恢复旧版时，须单独审查数据恢复方案。

升级保留原注册方式。要启用注册审核，请再按 [注册审核](Registration-Approval.zh-CN.md) 设置 `registrationMode: approval`。若曾在 Nginx 阻断注册 API，需自行调整该规则。

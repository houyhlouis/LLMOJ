# Prepare a GitHub release

[English publishing guide](../wiki/Publishing.md) | [中文发布教程](../wiki/Publishing.zh-CN.md)

Create a fresh source archive from a Git checkout with `python3 deploy/prepare-github.py --archive release/llmoj-source.tar.gz` (tracked files only; `--include-untracked` adds non-ignored untracked ones); the destination must not exist. In an installed copy without `.git` the tool prints how to check out the installed revision instead. Extract its LibreOJ/ directory and initialize a clean repository, preserving licenses and notices. Source packages exclude old Git history, actual config, keys, runtime data, rootfs and build output; the tool stops when a tracked file is neither source nor covered by a named exclusion (see SOURCE-PACKAGE.md), so a release can't silently miss one.

Replace repository placeholders in both README languages and Wiki examples before publishing. Public visibility enables anonymous installation. Export both Wiki languages with deploy/export-wiki.py; Home is Chinese, Home.en is English, and Home.zh-CN remains a compatibility page. Commit wiki/*.md in the main repository; updating the GitHub Wiki tab requires a separate commit to the OWNER/REPOSITORY.wiki.git checkout; `python3 deploy/export-wiki.py --compare WIKI_CHECKOUT` reports pages that differ (exit status 1) so drift is visible before a release. See the linked publishing guides for the GitHub Desktop workflow. Packing/exporting only writes local files; no repository is created or pushed automatically.
